# 凭据保险库·whitepaper·v2.1-cn（说明文档）

## 产品定位与场景 - 1

凭据保险库（Credential Vault，代号 CREDV）隶属于Agent 身份、凭据和权限场景，当前生命状态ACTIVE，当前版本线 v2.1。其 核心协议 的取值/配置为 KMS-信封、多并行因子 ，约束条件包括支持 KMS-信封、支持 多并行因子。

在企业版部署中，凭据保险库 将 事件摄取吞吐 设计为 450000 events/s，并受到 enterprise-edition、3-node 的边界约束；相关细节记录的 fact_id 为 P004-F062，自 2025-06-01 起生效。

凭据保险库 面向 Agent 身份、凭据和权限 的高隔离要求，其 API 峰值并发 被定为 8000 req/s；叠加 enterprise-edition 之后，可支撑 450000 events/s 的吞吐基线，覆盖 cn 区域。

从运维视角看，凭据保险库 在 v2.1-cn 上的 P95 检索延迟 表现稳定为 12 ms，p95、warm；这一口径与相邻产品 P003 的 Agent 身份、凭据和权限 联合方案保持一致。

凭据保险库 的产品资料强调 最大单文档上传；在默认配置下等于 32 MB，约束为 默认限制。当工作负载包含 密钥、令牌、轮换、加密、凭据、保险库、访问、审计 等能力维度时，上述约束保持不变。

Credential Vault（CREDV）的 日志/审计留存期 记为 730 days，限定条件 默认；该数值服务于 Agent 身份、凭据和权限，由 v2.1-cn 版本正式支持。

关于 凭据保险库 的 批量接口吞吐，文献给出的标准口径为 9800 ops/s，并附加 batch=1024 说明；这是评估 Agent 身份、凭据和权限 能力时的重要依据（P004-F067）。

凭据保险库 v2.1-cn 的 当前版本线 配置为 v2.1 version；在 GA 场景下仍能维持 12 ms 的 P95 延迟，符合 cn 区域的运营要求。
