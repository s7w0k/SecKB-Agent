# Agent 行为审计与观测 — 故障排查

## 现象一：事件采集延迟/丢失
- 排查步骤：检查采集端网络与 Kafka 消费积压；查看采集器日志与上报队列状态
- 检查 Kafka 分区数与存储写入速率是否匹配；核对采样率与并发配置
- 定位点为"链路优先"：从采集端到存储端逐段验证吞吐与延迟

## 现象二：查询变慢/报表超时
- 排查步骤：检查数据量级与索引是否建立；查看查询是否命中全量扫描
- 检查集群节点负载与存储 IO；核对是否缺少按时间/会话的索引
- 定位点为"索引与资源优先"：优化索引与扩容存储节点

## 现象三：误报/漏报
- 误报：检查基线是否过旧、规则阈值过低；核对脱敏与白名单配置
- 漏报：确认采集范围完整、采样率未遗漏关键事件；核对告警规则生效状态
- 定位点为"规则优先"：重训基线与复核规则配置

## 现象四：集成失败（SDK/API）
- 排查步骤：核对 SDK 版本兼容性；检查鉴权 Token 与端口连通性
- 检查 Trace ID 注入是否生效；查看服务端错误码与日志
- 定位点为"接口优先"：抓取请求/响应报文比对 OpenAPI 文档

## 通用建议
- 收集采集器与存储日志目录 `/var/log/audit/`，保留现场后联系售后
- 提供产品版本号、事件 ID、查询语句与复现步骤便于快速定位
