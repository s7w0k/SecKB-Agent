# 模型安全红队评估平台 — 故障排查

## 现象：评测性能下降、吞吐骤减
- 检查评测节点 CPU/内存是否被其他任务占用，确认节点数是否满足并发需求
- 核对目标模型 API 限流配额，避免触发限频导致请求排队
- 查看 Redis 连接池与 PostgreSQL 慢查询，必要时扩充执行节点并重启编排服务

## 现象：误报/漏报（判定结果异常）
- 确认判定策略与威胁类别规则是否配置正确，优先使用多模型投票降低误报
- 检查目标模型是否启用了内容过滤导致攻击被系统层面拦截（应视为防御有效而非漏报）
- 升级攻击模板库至最新版，排查自定义模板语法错误

## 现象：集成失败（模型接入/CI 对接）
- 核对模型 API Key 与鉴权方式，使用控制台连通性测试定位鉴权错误
- CI 对接失败时检查 Webhook 回调地址网络可达性与签名校验配置
- 确认 SDK 版本与平台版本兼容，参照集成文档核对接口参数

## 现象：服务异常（崩溃/无响应）
- 查看编排中心与执行节点日志，优先定位 OOM 与磁盘满告警
- 检查数据库连接数上限，必要时扩容并重启相关服务
- 若为集群部署，检查 Pod 资源限制（limits）是否过低导致被驱逐

## 通用排查步骤
- 收集平台日志、评测任务 ID、目标模型响应样本，联系技术支持并附时间范围
- 参考运维手册核对版本号，确认是否可升级到修复相关缺陷的最新 patch
